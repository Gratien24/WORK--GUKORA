# WORK GUKORA — Render-ready

## What is included
- Node.js + Express backend at `/api`
- `/health` health-check endpoint
- Signed HTTP-only session cookies
- Password hashing with Node `scrypt`
- Admin dashboard and transaction approval/rejection
- PWA manifest, service worker, and icons
- Render Blueprint configuration

## Render
The included `render.yaml` uses:
- Runtime: Node
- Build: `npm ci`
- Start: `npm start`
- Health check: `/health`
- `NODE_ENV=production`
- `SESSION_SECRET` generated by Render
- `ADMIN_EMAIL` and `ADMIN_PASSWORD` entered manually

Render supports these Node/Express web-service settings and expects the app to listen on `0.0.0.0` and the `PORT` environment variable. See the official Render docs.

## Important before real-money use
The JSON store in `data/store.json` is a demo/testing datastore. A Render service filesystem is not a suitable production database for user balances and financial transactions. Use a persistent database such as Render Postgres before accepting real money.

The investment return figures shown in the UI are examples only and are not guaranteed. Connect payments only through an appropriate licensed provider and publish clear legal/risk/fee terms.

## Local test
1. Install Node.js 20+.
2. Run `npm ci`.
3. Set `SESSION_SECRET`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD`.
4. Run `npm start`.
5. Open `http://localhost:10000`.
6. Check `http://localhost:10000/health`.
